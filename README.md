# Дуркометр 2.0

Частная веб-лаборатория разбора переписок для Netlify. Текст, до четырёх скриншотов, drag-and-drop и вставка из буфера. На выходе: шуточный индекс дичи, цитаты с объяснениями, альтернативная трактовка, недостающий контекст и готовый ответ. Анализ касается конкретных реплик и поведения, а не психического здоровья или интеллекта людей.

## Запуск на Netlify

1. В Netlify выберите **Add new project → Import an existing project → GitHub → m0peterson/durka2**.
2. Ветка: **main**. Параметры уже лежат в `netlify.toml`: build `npm run build`, publish `dist`, functions `netlify/functions`. Node.js 22.
3. В **Project configuration → Environment variables** добавьте переменные ниже. Если доступен выбор scope, выберите **Functions**. Для секретов включите **Contains secret values**, если эта опция доступна на вашем тарифе. Если выбора scope нет, runtime-переменные всё равно остаются на сервере: сборка этого проекта не встраивает их в клиент.
4. Выполните **Deploy**. Если переменные добавлены после первой сборки, запустите новый deploy, чтобы функции получили их значения.
5. Откройте сайт и введите `APP_PASSWORD`. API-ключ в форме входа не нужен.

Обязательные переменные:

| Переменная | Значение |
|---|---|
| `APP_PASSWORD` | Собственный длинный случайный пароль для входа, от 16 символов, до 256 |
| `SESSION_SECRET` | Отдельная случайная строка минимум 32 символа для подписи сессий |
| `OPENROUTER_API_KEY` | Ваш ключ OpenRouter. Можно заменить на `GEMINI_API_KEY`, если OpenRouter не нужен |

Сгенерировать случайную строку локально: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Для пароля и секрета выполните команду отдельно.

**Не добавляйте ключи в GitHub, HTML, netlify.toml, переменные VITE_/NEXT_PUBLIC_ или чат.** Они вводятся только в панели Netlify. Собственная админка для токенов не требуется: роль защищённой админки выполняет панель Netlify.

Подключайте GitHub-репозиторий, а не загружайте папку `dist` через Netlify Drop: приложению нужны серверные Functions, статической публикации недостаточно.

## Модели и другие источники

- **OpenRouter:** по умолчанию `openai/gpt-6-luna` и `google/gemini-2.5-flash-lite`. Список моделей, приём изображений, доступные уровни effort и цены проверяются через `/api/v1/models`. Каталог кэшируется на сервере на пять минут. GPT-6 Luna выбирается первой, и при наличии поддержки режим `max` выбран по умолчанию.
- **Google напрямую:** задайте `GEMINI_API_KEY`. Появится Gemini 2.5 Flash-Lite через OpenAI-совместимый API Google, без OpenRouter. Используются стандартные настройки рассуждения этой модели.
- **Другой OpenAI-совместимый сервис:** задайте `COMPATIBLE_API_KEY`, `COMPATIBLE_BASE_URL` (HTTPS base URL до `/chat/completions`, обычно оканчивается на `/v1`) и `COMPATIBLE_MODEL`. Если модель принимает изображения в `image_url`, добавьте `COMPATIBLE_VISION=true`. По умолчанию это источник только для текста. Сервис должен поддерживать Chat Completions и `response_format: {type: "json_object"}`. Нестандартные API требуют адаптера; совместимость с произвольным провайдером не гарантируется.

Чтобы добавить модели OpenRouter, задайте `OPENROUTER_MODELS` списком ID через запятую. Это серверный разрешённый список: пользователь сайта не может передать произвольную дорогую модель или адрес API. Когда каталог доступен, отсутствующие в нём ID не показываются. При сбое каталога показываются настроенные ID с предупреждением, без подтверждённых цен; изображения разрешены только для двух известных моделей по умолчанию.

Нет скрытого переключения источника или автоматического повтора: переписка отправляется только выбранному провайдеру. При его отказе можно вручную выбрать другой. Для внешнего провайдера отдельно проверьте цену и политику обработки данных.

## Ограничения расходов и безопасность

- Ключи читаются в Netlify Functions из runtime environment. В браузер и статическую сборку они не попадают. Сборка копирует только `public/`.
- Вход обязателен. Если пароль или секрет не настроены, анализ закрыт. Cookie имеет `HttpOnly`, `Secure` на HTTPS, `SameSite=Strict`, префикс `__Host-`, срок 8 часов. Пароль не сохраняется в localStorage/sessionStorage.
- POST/DELETE требуют совпадающий Origin и JSON. Альтернативные адреса `/.netlify/functions/*` закрыты, чтобы не обходить ограничения основного пути.
- Netlify rate limit: 6 запросов анализа/минуту/IP и 15 обращений к endpoint сессии/минуту/IP. Эти правила исполняются на Netlify, не локальным dev-сервером. После deploy проверьте их принятие в deploy log, раздел post-processing. Это не глобальная денежная квота: несколько IP могут сделать больше запросов. Настройте небольшой лимит расходов на отдельном ключе у провайдера.
- Лимит текста 16 000 символов, до 4 изображений PNG/JPEG/WebP, запрос до 4 MB. Изображения проверяются по формату и сигнатуре. Браузер сжимает их и перерисовывает на canvas, без исходных EXIF-метаданных. Длинные скриншоты лучше предварительно разделить, чтобы сохранить читаемость.
- `MAX_OUTPUT_TOKENS` ограничивает общий бюджет ответа и reasoning для глубоких режимов: по умолчанию 16 000, допустимо 4096–32000. Быстрые режимы ограничены 4096. Max effort не означает минимальную задержку или фиксированную стоимость. При исчерпании бюджета пользователь увидит ошибку вместо выдуманного результата.
- Синхронная функция Netlify ограничена 60 секундами. Запрос провайдеру прерывается через 48 секунд; вместе с загрузкой каталога это оставляет запас. На max сложный разбор может не успеть. Выберите low или другую модель. Таймаут/закрытие страницы не гарантируют отмену списания у провайдера. Автоповторов нет.
- Ответ модели проверяется по форме и диапазону оценки, выводится через `textContent`, без выполнения HTML. Ошибки и reasoning провайдера клиенту не пересылаются. В приложении нет логирования текстов, скриншотов или ключей.
- Приложение не сохраняет историю на сервере или в хранилище браузера; материалы находятся в памяти страницы до очистки/перезагрузки. Переданные данные могут храниться у LLM-провайдера согласно его политике; действуют также правила инфраструктуры Netlify.
- Выход удаляет cookie этого браузера. При компрометации сессии смените `SESSION_SECRET` или `APP_PASSWORD` и выполните новый deploy: это аннулирует все прежние сессии. Индивидуального серверного списка отозванных сессий нет.
- Внешний вид страницы и исходный код общедоступны. Приватны доступ к анализу и серверные секреты. Это приложение для владельца и доверенных людей с общим паролем, не многопользовательский SaaS.

## Разработка и проверки

Без production-зависимостей, без базы данных. Node.js 22+.

```sh
npm ci
cp .env.example .env
# Заполните .env своими значениями. Файл исключён из git.
npm run dev
# http://localhost:8888
npm test
npm run build
```

`scripts/dev.mjs` слушает только loopback. Для проверки платформенной маршрутизации можно отдельно использовать Netlify CLI (`netlify dev`). Платформенные лимиты нужно проверять после настоящего deploy.

Автотесты проверяют закрытый по умолчанию доступ, cookie, подделку и истечение сессий, смену пароля, CSRF, альтернативные URL, размер/формат входа, разрешённые модели, бюджет токенов, сокрытие ключа и обработку ответа провайдера. GitHub Actions запускает их и статическую сборку при push/PR.

Проверка с реальным оплачиваемым провайдером требует вашего настроенного ключа. Она не входит в mock-тесты. После deploy проверьте вход, один текстовый разбор, один разбор скриншота и отказ `/api/analyze` без cookie.
